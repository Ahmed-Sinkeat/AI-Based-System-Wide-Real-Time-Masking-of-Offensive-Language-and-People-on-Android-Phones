1. Introduction

1.1 Purpose

This document explains what HaramBlurr must do and how well it must do it. It is written for the project team and supervisors, so it avoids deep technical detail. The full technical study and the test results live in investigation-linux-v1.md and p0-results-linux-v1.md.

1.2 The problem

Some people want to avoid seeing images of people while they use a computer: in social feeds, videos, ads, news and games. Today's tools record the screen, look at it, then draw a blur on top. That has three problems:

  • The content is shown before it is checked, so it flashes on screen for a moment.
  • They work like screen recording, which is heavy and asks for screen-sharing permission.
  • They often work only in one app or one website.

1.3 Our idea

HaramBlurr sits inside the part of Linux that draws all windows on the screen. It sees each window's picture before it reaches the screen. Anything new stays hidden until it has been checked. Only then is it shown, with any people covered.

2. Overview

2.1 How it works, simply

  • The display part runs inside the desktop. It takes a small copy of each window when it changes and applies the cover.
  • The detection part is a separate background program. An AI model finds the people in that copy and sends back where they are.
  • The two are separate on purpose. If detection crashes, the desktop keeps running and new content stays hidden.
Content changesnew image, scroll, video frame
Covered while checkedabout 40–50 ms (2–3 frames)
Shownwith every detected person hidden

2.2 Users

One kind of user: a person who chooses to install the filter on their own computer. It is a personal tool, not a parental-control or monitoring tool.

2.3 Where it runs

ItemVersion 1
SystemLinux, with the Hyprland desktop (version 0.56)
Target laptopIntel Core i5 (11th gen), built-in Intel Iris Xe graphics, 8 GB memory. A normal student laptop, no gaming graphics card.
InternetNot needed. Everything runs on the device.

2.4 Assumptions

  • The user runs Hyprland and agrees to install a plugin for it.
  • "Person" means any human figure: real, drawn, animated or in a game.
  • Hiding something by mistake is acceptable. Showing a person by mistake is not. When in doubt, hide.

5. Not in version 1

  • Android and other phones
  • Other Linux desktops (GNOME, KDE Plasma) and old X11 sessions
  • Hiding only some people, for example by gender. This is much less accurate, and a mistake means a person is shown.
  • Blocking the user from turning the filter off. It is a personal choice, not a lock.
  • HDR screens and computers with more than one graphics card

8. Terms

FrameOne picture on the screen. A normal screen shows 60 per second, so one frame is about 17 ms.
msMillisecond, one thousandth of a second.
HyprlandThe Linux desktop program that draws all windows on the screen. Our display part is a plugin for it.
AI modelThe trained program that finds people in a picture.
Hide firstOur rule: new content stays covered until it is checked (in technical documents: "fail-closed").
